## 2. 목표와 비목표

- 목표
  - 문제 폴더(`Lv0_.../01_.../`)를 읽어 목록으로 보여 주고, 파일을 열어 편집·자동 저장.
  - Java, Python, JavaScript 로 작성한 풀이를 실행(입출력 문제)하고 시험(함수 작성 문제)한다.
  - 입력을 자동으로 채우고, 시험 케이스를 저장해 한 번에 다 돌리고 통과·실패를 본다.
  - 사이트에 붙여 넣을 "코드 전체 복사" 버튼과 단축키.
- 비목표(지금 하지 않음)
  - 사이트의 숨은 테스트(채점용)는 알 수 없으므로 사이트 채점을 대신하지 않는다. 시험은 1차 확인용이다.
  - 사이트 로그인·자동 제출.
  - DB 저장(풀이는 파일이 원본).
  - 배포·판매(개인용 전제).
  - 클라우드·계정·푸시 알림.

## 4. 설계와 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 풀이는 문제 폴더의 소스 파일(`.java`, `.py`, `.js`)이 원본이고 exe 는 읽고 쓴다 | VS Code·git 과 같이 쓸 수 있고 75문제 규모에 DB 는 과함 | SQLite DB(VS Code·git 에서 못 봄), md 파일에 코드 블록(추출이 번거로움) |
| 문제 루트 폴더는 설정에서 고른다(기본 `C:\dev\AcademicTest`) | 폴더 위치가 바뀌어도 앱 수정 없음 | 경로 하드코딩 |
| 언어는 파일 확장자로 판별하고, 문제 폴더 하나에 언어별 파일이 같이 있을 수 있다 | 같은 문제를 자바·파이썬으로 풀 수 있음 | 언어별 별도 폴더 트리 |
| 실행기(러너)는 언어마다 하나씩 두는 플러그인 구조: 컴파일(선택) → 실행 → 입력 전달 → 시간 제한 → 출력 수집 | 언어를 추가해도 다른 곳을 안 고침 | 언어마다 화면·로직 복제 |
| 임시 폴더에 컴파일·실행하고 끝나면 지운다 | 문제 폴더에 `.class` 등이 남지 않고 `Main` 이름 충돌이 없음 | 폴더 안에 컴파일 |
| 입출력 문제는 입력 창(자동 채움: 지난 입력·저장된 케이스)으로 실행한다 | 매번 직접 입력하지 않음 | 항상 터미널 입력 |
| 함수 작성 문제(`Solution`)는 시험용 래퍼(하니스)를 자동 생성해 실행한다: 케이스의 인수(JSON)를 매개변수 타입으로 읽어 `solution` 호출 후 결과를 기대값과 비교 | main 이 없어도 시험 가능 | "채점 안 함"(사용자 요구가 커져 확대) |
| 시험 케이스는 앱 데이터 폴더(`%APPDATA%\AcademicRunner\cases.json`)에 둔다 | 과제 폴더를 건드리지 않음(과제 폴더 변경을 원치 않는다고 함) | 문제 폴더에 케이스 파일 |
| "시작 코드와 다름" 여부는 `original/` 의 같은 문제 파일과 비교해 "작성함" 표시로 보여 준다. 완료 표시는 사용자가 체크 | 진행 현황이 보임 | 자동 완료 판정(정답을 알 수 없음) |
| 편집기는 Monaco(Java·Python·JS 하이라이트) | VS Code 와 같은 편집 경험 | 단순 textarea |
| 메인 프로세스와 화면은 분리(contextIsolation, nodeIntegration 끔), 파일·실행은 허용 목록 IPC 로만 | 사용자 코드를 실행하는 앱이라 격리가 중요 | 화면에서 직접 Node 사용 |
| 실행 안전장치: 시간 제한(기본 10초), 출력 크기 상한, 중지 버튼, 문제 루트 밖 경로 거부 | 무한 반복·거대 출력·경로 조작 방지 | 제한 없음 |
| 라이트/다크: 시스템 설정을 따르고 수동 전환·저장 | `rules\core\theme.md` | 단일 테마 |
| 실행 환경(JDK, Python 경로)은 설정에서 고른다(자동 탐색 후 확인) | PC 마다 다름 | 경로 고정 |

### 4-1. 화면

- 상단 바: 앱 이름, 빠른 이동(검색), 언어 선택, 라이트/다크, 설정.
- 좌측: 단계 → 문제 목록(번호·제목·상태: 작성함/완료/미작성), 필터.
- 중앙: 편집기(탭: 언어별 파일), 위쪽에 저장 상태·복사·되돌리기 버튼.
- 하단 패널: 입력 / 출력 / 시험 케이스 탭, 실행·중지·컴파일 버튼.
- 하단 상태줄: 사용 중인 JDK·Python 버전, 마지막 실행 시간.

### 4-3. 편의 기능

- 마지막에 연 문제·언어·패널 크기 복원, 자동 저장(마지막 입력 후 약 0.8초).
- 입력 자동 채움: 마지막으로 넣은 입력 기억, 저장한 케이스 목록에서 선택.
- 케이스 전부 실행 후 통과·실패와 기대/실제 출력 차이를 보여 준다.
- 외부 편집 감지: VS Code 에서 같은 파일을 고치면 알리고, 불러올지 묻는다(마지막 저장 우선, 충돌 시 알림).
- 출력 복사, 실행 시간 표시.

## 6. 검증 방침

- 테스트(`node:test`): 문제 폴더 스캔, 언어·문제 유형 판별, 경로 검증(루트 밖 거부), 하니스 생성, 러너(컴파일·실행·시간 초과·중지). 모두 **임시 폴더와 가짜 문제**만 쓰고 실제 `AcademicTest` 는 읽기만 한다.
- 컴파일러가 없는 환경에서는 해당 러너 시험을 건너뛰고 건너뛴 사실을 보고한다.
- 눈으로 확인: 라이트·다크 양쪽, 폰 폭은 해당 없음, 작업 표시줄 고정(exe 아이콘).
- 수락 기준: 75개 문제 스캔 성공 / 입출력 문제 3개 이상을 앱에서 실행 / 시험 케이스 통과·실패 판정 / 시간 초과 10초에서 중지 / 문제 루트 밖 파일 접근 거부.

## 8. 열린 질문

- 처음 지원할 언어: Java, Python, JS 로 정해 두었다. C/C++ 가 필요한가(필요하면 gcc 설치가 먼저).
- 문제 설명도 앱에서 보고 싶은가(사이트를 읽어 저장). 지금은 계획에 넣지 않았다.
- "완료" 표시는 직접 체크로 한다(자동 판정 불가). 괜찮은가.
- 실행 방식은 PC 의 JDK·Python 을 쓰는 것으로 가정(가정). 다른 PC 에 옮길 일은 없다고 본다.
