# 진행 현황

> 문제마다 "안 품 / 작성 중 / 통과" 를 목록에 표시하고, 상태로 걸러 볼 수 있다.

## 상태 기준

| 표시 | 뜻 |
| --- | --- |
| 빈 원 (안 품) | 첫 풀이 파일이 시작 코드(original 폴더의 사본)와 같음 |
| 반쪽 원 (작성 중) | 시작 코드에서 바뀌었지만, 통과 기록이 없거나 통과한 뒤 또 고침 |
| 꽉 찬 원 (통과) | 저장된 시험 케이스를 전부 통과했을 때의 코드와 지금 코드가 같음 |

- 코드 비교는 줄바꿈(CRLF/LF), 줄 끝 공백, 끝의 빈 줄을 무시한다.
- 시작 코드(original)를 찾을 수 없으면 내용이 있는 코드는 작성한 것으로 본다.
- 통과는 "케이스 전체 실행(F7)"이나 제출 전 점검에서 케이스가 1개 이상이고 전부 통과했을 때만 기록한다. 중지했거나 케이스가 0개면 기록하지 않는다.

## 화면

- 목록 위: 진행 상태 필터(전체 상태, 안 푼 문제, 작성 중, 통과, 오늘 통과)와 "통과 N / 작성 중 N / 전체 N" 요약. 검색·단계 필터와 함께 적용된다.
- "오늘 통과"는 오늘 날짜(PC 시각 기준)에 통과했고 지금도 통과 상태인 문제다.
- 저장·시작 코드로 되돌리기·실행이 끝나면 바로 갱신된다.

## 저장 위치

- 코드가 바뀌었는지는 메인 프로세스가 파일을 읽기만 해서 계산한다(`problems:progressAll`, `problems:progressOne`).
- 통과 기록(코드 해시와 날짜)은 앱 화면 저장소(localStorage `academicrunner.progress`)에만 둔다. 문제 폴더에는 아무것도 쓰지 않는다.
- 해시: 정규화한 코드의 SHA-1 앞 16자리. 실행 결과에 실행한 코드의 해시를 실어 보내므로, 실행 중에 코드를 고쳐도 실제로 통과한 코드로 기록된다.

## 용어

- **해시**: 코드 내용을 짧은 값으로 줄인 지문. 코드가 한 글자라도 다르면 값이 달라진다.
- **정규화**: 의미 없는 차이(줄바꿈 종류, 줄 끝 공백)를 없애 같은 코드로 비교하는 일.
