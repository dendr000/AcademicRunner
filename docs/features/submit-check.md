# 제출 전 점검

## 무엇인가

학원 사이트에 코드를 붙여 넣기 전에 흔한 실수를 한 번에 확인하는 기능입니다. 편집기 위의 `제출 전 점검` 버튼, `파일 > 제출 전 점검...`, 또는 `Ctrl+Shift+Enter`(설정에서 변경 가능)로 엽니다.

## 점검 순서

1. **저장 확인:** 저장하지 못한 변경이나 충돌이 있으면 여기서 멈춥니다.
2. **코드 점검(정적):** 코드를 읽어 아래를 확인합니다.
3. **컴파일(문법) 확인:** 실행 패널의 컴파일 확인과 같습니다.
4. **시험 케이스 전부 실행:** 저장된 케이스가 있으면 전부 돌려 통과 개수를 봅니다. 컴파일에 실패했으면 건너뜁니다. 케이스가 없으면 "예제 입출력을 케이스로 저장해 두라"는 주의를 보여 줍니다.

각 항목은 **통과 / 주의 / 실패** 로 표시되고, 맨 아래에 전체 판정이 나옵니다. 끝나면 그 자리에서 `복사하기`(실패가 있으면 `그래도 복사`)로 코드 전체를 클립보드에 복사합니다. `Esc` 나 `닫기` 는 진행 중인 점검을 중지합니다.

## 코드 점검 항목

| 언어 | 실패 | 주의 |
|---|---|---|
| 공통 | 코드가 비어 있음 | `TODO`·`FIXME` 표시, 디버그용 출력(`debug`), 함수 문제에서 표준 입력 읽기 |
| Java 입출력 | `package` 선언, public class 이름이 `Main` 이 아님, `main` 메서드 없음 | public class 없음, 출력문 없음 |
| Java 함수 | `class Solution` 없음, `solution(...)` 메서드 없음 | |
| Python | 함수 문제에 `def solution` 없음 | 입출력에 `print` 없음, `breakpoint()`/`pdb` |
| JavaScript | 함수 문제에 `solution` 함수 없음 | 입출력에 `console.log` 없음, `debugger` |

주석 안의 내용은 무시합니다(주석으로 막아 둔 `package` 는 실패로 세지 않음).

## 알아둘 점

- 점검 중에는 실행·컴파일·케이스 실행 버튼과 단축키가 막힙니다(같은 실행 엔진을 쓰기 때문).
- 점검은 문제 폴더에 아무것도 쓰지 않고(임시 폴더에서 실행), 시험 케이스도 바꾸지 않습니다.
- 정적 점검은 글자 패턴으로 찾으므로 100% 는 아닙니다. 사이트의 채점 결과를 대신하지 않습니다.

## 용어 설명

| 용어 | 뜻 |
|---|---|
| 정적 점검 | 프로그램을 실행하지 않고 코드 글자만 읽어서 하는 점검 |
| 시험 케이스 | 입력과 기대 출력 한 쌍 (케이스 탭에서 만듦) |

## 관련 파일

- `src/ui/submit-check.js` 점검 규칙과 결과 판정 (화면 없는 순수 함수)
- `src/ui/submit-flow.js` 점검 순서 진행과 결과 창
- `src/ui/run-panel.js` `setExternalBusy` (점검 중 실행 막기)
